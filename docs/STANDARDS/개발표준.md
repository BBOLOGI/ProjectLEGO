# 개발표준

## 목적

Project LEGO 개발 작업의 기본 품질 기준과 수행 흐름을 정의한다.

## 적용 범위

Project LEGO 저장소에서 수행하는 구현, 수정, 시험 및 배포 준비 작업에 적용한다.

## 개발 작업 순서

TASK와 SPEC 확인 → 기존 상태 조사 → 구현 → Build → Test → Commit → Push 순서를 기본으로 한다.

## Build 기준

대상 솔루션은 오류 없이 빌드되어야 하며, 경고는 저장소 설정에 따라 처리한다.

## Test 기준

변경과 관련된 시험 및 기존 전체 시험이 통과해야 한다. 실패는 숨기지 않는다.

## Commit 기준

하나의 명확한 변경 단위로 작성하고 `Commit_규칙.md`를 따른다.

## Push 기준

검증과 변경 검토를 마친 커밋만 기준 브랜치 또는 승인된 작업 브랜치에 Push한다.

## 완료 기준

TASK에 명시된 필수 결과물과 검증을 충족하고 Commit과 Push를 완료한다.

## 중단 기준

요구사항 불명확, 기존 파일 충돌, Build/Test 실패 또는 Git 충돌 시 임의로 진행하지 않는다.

## 외부 서비스 장애 처리

503, Timeout 등 일시 장애는 프로젝트 오류와 구분하고 현재 변경을 보존한 뒤 복구 후 재개한다.
